# 阶段一：项目与接口管理

## 1. 目标与边界

用户可以创建项目、导入 YAML、浏览接口、更新文件并查看历史版本。本阶段不实现任务或 HTTP 执行能力，也不依赖这些能力验收。

## 2. 项目管理

- 项目字段：ID、名称、描述、创建时间、更新时间。名称必填且系统内唯一。
- 支持列表、按名称搜索、创建、编辑、详情和删除。详情展示文件及当前版本接口数量。
- 删除需二次确认，提示关联数据范围，确认后删除项目及所属文件、版本和接口。后续阶段新增的任务及运行记录同样纳入关联删除；存在运行中任务时禁止删除项目。

## 3. YAML 格式与解析

- 接受 UTF-8 的 `.yaml`、`.yml` 文件，采用 OpenAPI 3.0.x；单文件上限 5 MiB。
- 解析 `paths` 下 HTTP 操作，记录方法、路径、operationId、摘要、描述及响应定义。
- 支持 path、query、header 参数及 application/json 请求体，保留类型、必填、默认值、示例和字段结构。
- Schema 支持 string、integer、number、boolean、array、object 和嵌套结构；支持文件内 `#/components/...` 引用。
- 暂不支持外部引用、组合 Schema（oneOf、anyOf、allOf）、cookie 参数及非 JSON 请求体。不支持的结构需定位并拒绝导入，不得静默丢弃。
- 空文件、无接口、非法 YAML、非法 OpenAPI、引用无法解析或超限均拒绝导入。认证定义仅供浏览，不自动生成认证请求头。
- `servers` 可展示，执行地址由阶段二任务明确配置。

## 4. 导入、更新与版本

- 进入项目上传文件并填写逻辑文件名，同项目不可重名；校验通过后一次性保存文件、版本 1、原始内容和接口集合。
- 导入失败返回字段或路径等具体位置，不生成部分数据。
- 文件列表展示名称、当前版本、接口数量、更新时间；接口列表支持按方法、路径筛选，详情展示参数、请求体和响应定义。
- 选择逻辑文件上传新 YAML，成功后新增递增版本并切换当前版本。新集合完全以新文件为准，包括新增、修改和移除接口。
- 更新失败不改变当前版本及历史数据；历史版本不可编辑，可查看对应接口及经过敏感信息处理的原始内容。
- 不提供版本回滚、差异对比或单个历史版本删除。
- 删除逻辑文件需二次确认；阶段二开始，任意版本被任务引用时阻止删除并提示引用任务。

## 5. 页面交付

项目列表与编辑入口、项目详情、文件导入及更新入口、版本列表、接口列表和详情，包含空状态与解析失败反馈。

## 6. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| P1-01 | 创建、搜索、编辑、删除项目 | 数据持久化，重名被拒绝，关联删除符合约定 |
| P1-02 | 导入含 GET、POST、路径参数及嵌套请求体的文件 | 数量、方法、路径、类型及字段与样例一致 |
| P1-03 | 导入非法、外部引用、无接口或超限文件 | 具体错误可见，无部分数据 |
| P1-04 | 更新时新增、修改、移除接口 | 当前版本准确反映新集合，历史版本保持原集合 |
| P1-05 | 上传失败的更新 | 当前版本及历史列表不变化 |
| P1-06 | 不同项目导入同名文件 | 可以分别浏览、更新，互不影响 |

提供有效、更新和无效 YAML 样例。上述场景可通过浏览器独立验证，刷新或重启服务后数据仍存在。
